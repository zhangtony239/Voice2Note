# Spec Delta

## Purpose

定义一份录音任务从建立到结束的完整生命周期：任务与 token 的独立隔离、幂等开始、结束与重试与取消的语义、状态的推进规则、状态在本机的持久保存与重启恢复，以及并发上限与识别串行。云盘上的文件格式属于 `cloud-relay`，对外接口字段属于 `rec-daemon`。

## ADDED Requirements

### Requirement: 每份录音独立任务与独立本地目录

每份录音 SHALL 对应一个独立任务，拥有独立的任务 token、独立的状态记录和独立的本地工作目录。不同任务即使音频块编号相同 MUST 使用不同目录，MUST NOT 互相覆盖音频或原稿。

#### Scenario: 两台手机同时录音
- **WHEN** 两部手机用同一连接 token 同时建立任务，各自上传编号从 1 开始的音频块
- **THEN** 两个任务各自保存自己的音频与原稿，一个任务结束不影响另一个

#### Scenario: 同编号块不串资料
- **WHEN** 两个任务都在处理编号为 1 的音频块
- **THEN** 两个块的文件分别落在各自任务目录下，互不读写对方文件

### Requirement: 开始请求的幂等与冲突

开始请求 SHALL 以任务标识作为幂等键。同一任务标识重复提交且云盘路径相同时 MUST 返回原任务与原任务 token，不建立重复任务。同一任务标识配不同云盘路径时 MUST 返回冲突错误。对已取消的任务再次提交开始 MUST 返回冲突错误，MUST NOT 复活该任务。

#### Scenario: 开始响应丢失后重试
- **WHEN** 服务端已建立任务但客户端未收到响应并重试同一请求
- **THEN** 返回原任务标识、原任务 token 与当前状态，任务数量不变

#### Scenario: 同一标识换路径
- **WHEN** 客户端用已存在的任务标识但不同的云盘路径提交开始
- **THEN** 返回冲突错误，原任务不受影响

#### Scenario: 已取消任务再次开始
- **WHEN** 客户端对已取消的任务标识提交开始
- **THEN** 返回冲突错误，该任务不恢复轮询，客户端需使用新任务标识

### Requirement: 结束通知只携带任务 token

结束通知 SHALL 只包含任务 token 一个字段，服务端据此定位任务并进入收尾阶段。重复结束 MUST 幂等。收尾期间 MUST 继续等待最终清单与迟到文件，MUST NOT 因结束通知而丢弃尚未到达的块。结束通知 MUST NOT 触发任何笔记生成或模型整理请求。

#### Scenario: 结束先于最后一块到达
- **WHEN** 结束通知先到而云盘上最后一个音频块尚不可见
- **THEN** 任务进入收尾并继续等待，尾块到达后继续处理，最终集合完整才结束

#### Scenario: 收尾不产生笔记
- **WHEN** 任务收尾完成并发布完成标记
- **THEN** 服务端不发出任何大模型请求，也不生成任何笔记文件

### Requirement: 重试只补足未完成部分

重试 SHALL 保留已完成块、已上传原稿与已发布索引版本，只把失败块与校验未通过的块重置为待处理。重试后索引版本 MUST NOT 回退。对已完成或已取消的任务提交重试 MUST 返回冲突错误。

#### Scenario: 部分块失败后重试
- **WHEN** 一个块识别失败、其他块已完成，用户触发重试
- **THEN** 只重新处理失败块，已完成块不重复下载或重复识别

#### Scenario: 重试后索引版本不回退
- **WHEN** 任务已发布过若干版本的结果索引后执行重试并再次发布
- **THEN** 新版本号大于此前所有版本号

### Requirement: 取消停止任务并清理本地资料

取消 SHALL 幂等地停止该任务的轮询与识别，删除该任务的本地工作目录，MUST NOT 删除云盘上的任何文件。取消后 SHALL 保留一条最小的占位记录，使同一任务 token 的重复取消仍被识别并返回成功，MUST NOT 返回鉴权失败。已完成的任务被取消时 SHALL 同样清理本地工作目录并转为已取消状态。

#### Scenario: 手机删除记录
- **WHEN** 手机删除一份已完成录音记录并发出取消
- **THEN** 服务端停止该任务、删除其本地工作目录，云盘副本保留

#### Scenario: 重复取消
- **WHEN** 客户端因网络抖动重复提交同一取消请求
- **THEN** 每次都返回成功与已取消状态，不出现鉴权错误

#### Scenario: 取消不删云盘
- **WHEN** 任务被取消后检查云盘任务目录
- **THEN** 目录中的音频、清单与原稿仍然存在

### Requirement: 状态推进与不因时间失败

任务状态 SHALL 只在真实进展时推进，MUST NOT 因等待时间过长而自动转为失败。普通等待文件、等待清单、等待网络 MUST 被视为正常状态。块级失败 MUST NOT 把整个任务置为失败，任务仍可继续处理其他块。

#### Scenario: 长时间无新块
- **WHEN** 任务建立后手机长时间未上传新音频
- **THEN** 任务保持等待或接收状态，不自动失败

#### Scenario: 单块失败
- **WHEN** 某个块下载或识别失败
- **THEN** 任务状态保持接收或收尾，仅失败块计数增加，其他块继续处理

### Requirement: 状态在本机持久保存并在重启后恢复

任务的身份、结束标志、清单版本、索引版本与每块进度 SHALL 保存在本机状态目录，写入 MUST 采用先写临时文件再替换的方式。进程重启后 SHALL 恢复全部未结束任务及其 token、继续等待未到达的块，MUST NOT 重复把已完成块计为新块，MUST NOT 让索引版本回退。

#### Scenario: 收尾期间重启
- **WHEN** 任务收尾等待尾块时进程重启
- **THEN** 重启后同一任务 token 仍可用，已完成块保留，继续等待尾块

#### Scenario: 重启后 token 不变
- **WHEN** 进程重启后客户端用重启前的任务 token 查询任务
- **THEN** 鉴权通过并返回该任务，token 无需重新签发

### Requirement: 并发上限与识别串行

服务端 SHALL 限制同时活动的任务数量，超出上限时 MUST 拒绝新的开始请求并标记为可重试。识别调用 MUST 串行执行，同一时刻只允许一个识别在进行，MUST NOT 让多个任务同时进入模型推理。

#### Scenario: 超过活动任务上限
- **WHEN** 活动任务已达上限时收到新的开始请求
- **THEN** 返回可重试的拒绝原因，不建立任务

#### Scenario: 两部手机同时识别
- **WHEN** 两个任务同时有待识别音频块
- **THEN** 识别依次执行，两个任务都最终完成，不出现并发推理
